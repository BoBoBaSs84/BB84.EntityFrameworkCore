Remarks

The composition of IReadRepository<TEntity> and IWriteRepository<TEntity>, and the interface a repository implementation declares. It adds no members of its own.

Depend on one of the halves instead wherever a component only reads or only writes; the dependency then states in its type what it is allowed to do.

ExecuteDelete(Expression<Func<TEntity, bool>>)

Deletes all database rows for the TEntity instances which match the expression from the database.

public int ExecuteDelete(Expression<Func<TEntity, bool>> expression)

Parameters

expression Expression<Func<TEntity, bool>>

The condition to fulfill to be deleted.

Returns

int

The total number of rows deleted in the database.

Remarks

This operation executes immediately against the database, rather than being deferred until save changes is called. It also does not interact with the EF change tracker in any way: entity instances which happen to be tracked when this operation is invoked aren't taken into account, and aren't updated to reflect the changes.

This deletes permanently, even for soft deletable entity types. Because no save operation takes place, save changes interceptors never run, and the soft deletable interceptor therefore cannot turn the deletion into a flag update. The rows are gone. Use Delete(TEntity) together with a save operation to soft delete.

Stream(Query<TEntity>?, CancellationToken)

Streams the entities matching the specified query.

public IAsyncEnumerable<TEntity> Stream(Query<TEntity>? query = null, CancellationToken cancellationToken = default)

Parameters

query Query<TEntity>

The query describing what to read. Reads everything when omitted.

cancellationToken CancellationToken

The cancellation token to cancel the request.

Returns

IAsyncEnumerable<TEntity>

The matching entities, yielded as they arrive.

Remarks

Rows are yielded as they arrive instead of being buffered, which suits exports, batch jobs and other unbounded reads.

The sequence is lazy. It has to be enumerated within the lifetime of the context, and EF Core allows only one active stream per context at a time. Leave TrackChanges off, or the change tracker grows with every entity yielded and the point of streaming is lost.
